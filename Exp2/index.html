📚 REST API Endpoint Specifications

Reference guide for testing CRUD operations against http://localhost:3000/students

GET /students

1. Retrieve All Students

Fetches the full collection of student records from the database.

Expected Status: 200 OK
Sample Response (Array): 
[
  { "id": "S101", "name": "Aarav Sharma", "semester": 5, ... },
  { "id": "S102", "name": "Priya Patel", "semester": 4, ... }
]
GET /students/:id

2. Retrieve Single Student

Fetches a specific student record by unique identifier (e.g. S101).

Expected Status: 200 OK
Sample Response (Object): 
{
  "id": "S101",
  "name": "Aarav Sharma",
  "semester": 5,
  "department": "Computer Science & Engineering",
  "email": "aarav.sharma@example.com",
  "attendance": 88,
  "status": "On Track",
  "subjects": ["Data Structures", "DBMS", "Web Tech"]
}
POST /students

3. Add New Student

Creates a new student entity. Requires complete JSON payload in request body.

Expected Status: 201 Created
Sample Request Body: 
{
  "id": "S105",
  "name": "Vikramaditya Rao",
  "semester": 5,
  "department": "Computer Science & Engineering",
  "email": "vikram.rao@example.com",
  "attendance": 91,
  "status": "On Track",
  "subjects": ["AI", "Web Tech", "Cloud"]
}
PUT /students/:id

4. Full Replace Student

Completely replaces an existing student entity (e.g. S105).

Expected Status: 200 OK
⚠️ Note: PUT performs a full overwrite. Omitted fields will be permanently removed.
Sample Request Body: 
{
  "id": "S105",
  "name": "Vikramaditya Rao",
  "semester": 6,
  "department": "Computer Science & Engineering",
  "email": "vikram.rao.updated@example.com",
  "attendance": 95,
  "status": "Excellent",
  "subjects": ["AI", "Web Tech", "Cloud", "Deep Learning"]
}
PATCH /students/:id

5. Partial Update Student

Updates only specific fields (e.g. attendance or status of S102).

Expected Status: 200 OK
💡 Note: PATCH applies delta updates, modifying only provided properties while preserving unchanged fields.
Sample Request Body: 
{
  "attendance": 78,
  "status": "On Track"
}
DELETE /students/:id

6. Delete Test Student

Removes a test student record from the database (e.g. S105).

Expected Status: 200 OK / 204
⚠️ Best Practice: Create a new test student (using POST) before executing DELETE to preserve base dataset.
Target URL: 
DELETE http://localhost:3000/students/S105
HEAD /students

7. Inspect Response Headers

Retrieves HTTP response headers without returning a response payload body.

Expected Status: 200 OK
Observed Response Headers: 
Content-Type: application/json; charset=utf-8
Content-Length: 1248
Cache-Control: no-cache
Access-Control-Allow-Credentials: true
(Body: 0 bytes empty)

🛠️ Steps of Implementation

Complete walkthrough of how this REST API practice project was built from scratch.

1

Create Project Folder Structure

Set up the project directory with the following files:

Exp2/ ├── index.html (Dashboard UI) ├── style.css (Styling) ├── db.json (JSON Server Database) ├── CourseGap-Postman-Collection.json (Postman Collection) └── README.md (Documentation)
2

Create the db.json Database File

Define a students resource with at least 3 student entries. Each student object includes: id, name, semester, department, email, attendance, status, and subjects (an array).

{ "students": [ { "id": "S101", "name": "Aarav Sharma", "semester": 5, "department": "Computer Science & Engineering", "email": "aarav.sharma@example.com", "attendance": 88, "status": "On Track", "subjects": ["Data Structures", "DBMS", "Web Dev"] }, ... ] }
3

Install & Start JSON Server

JSON Server turns a plain db.json file into a full REST API with zero coding. Launch it with:

npx json-server --watch db.json --port 3000

This automatically creates all CRUD endpoints at http://localhost:3000/students.

4

Build the HTML Dashboard (index.html)

Create a clean, semantic HTML5 page containing:

  • Header — Project title, tech badges (JSON Server, Postman, Vanilla JS)
  • How to Run — Setup instructions with numbered steps
  • Student Data Table — Displays all student records from db.json
  • Endpoint Reference Cards — Visual cards for each REST method (GET, POST, PUT, PATCH, DELETE, HEAD)
  • API Sandbox — Interactive console to test live requests against JSON Server
  • Steps of Implementation — This section documenting the build process
5

Style the Dashboard (style.css)

Apply modern, responsive CSS3 styling including:

  • CSS Custom Properties (variables) for consistent theming
  • Color-coded CRUD method badges — GET POST PUT PATCH DELETE HEAD
  • Responsive grid layout using CSS Grid & Flexbox
  • Container queries for adaptive table layout on small screens
  • Google Fonts (Inter + Fira Code) for readability

Implement JavaScript for Live Data Fetching

Add vanilla JavaScript to:

  • Fetch live student data from http://localhost:3000/students using the Fetch API
  • Render data dynamically into the HTML table
  • Fall back to static embedded data when JSON Server is offline
  • Provide an interactive sandbox for sending GET and HEAD requests
7

Create Postman Collection (CourseGap-Postman-Collection.json)

Build a Postman v2.1 collection file with 7 pre-configured requests:

  1. GET /students — Retrieve all students
  2. GET /students/S101 — Retrieve single student
  3. POST /students — Add new student (with full JSON body)
  4. PUT /students/S105 — Full replace (with full JSON body)
  5. PATCH /students/S102 — Partial update (attendance & status)
  6. HEAD /students — Inspect response headers
  7. DELETE /students/S105 — Delete test student
8

Test All Endpoints in Postman

Import the collection into Postman and execute requests in the recommended order:

  1. GET All Students → verify 200 OK + full array
  2. POST Create S105 → verify 201 Created
  3. GET Fetch S105 → verify creation succeeded
  4. PUT Replace S105 → verify 200 OK (full overwrite)
  5. PATCH Update S102 → verify only supplied fields changed
  6. HEAD Inspect headers → verify headers with empty body
  7. DELETE Remove S105 → verify 200 OK / 204
9

Understand PUT vs PATCH

PUT Full Replacement

  • Replaces the entire resource object
  • Omitted fields are deleted
  • Must send all fields in request body
  • Idempotent — same request always produces same result

PATCH Partial Update

  • Updates only supplied fields
  • Omitted fields are preserved unchanged
  • Send only the fields you want to change
  • More efficient for single-field edits
